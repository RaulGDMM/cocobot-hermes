# Video-model ecosystem — moves fast, re-verify before relying

Re-homed from the former ai-model-news-research (research snapshots 2026-08-30 / 2026-10-02) — this is the video-model half of that skill; LLM-model status lives in ai-model-intel.

## MiniMax H3
- **Open weights OUT** since 2026-08-03: `MiniMaxAI/MiniMax-H3` on HF (~288 GB, MiniMax H3 Community License; BF16 checkpoints `FL2VA` + `Ref2VA`; full-attention inference only in the initial release).
- **H3-Regenerate-2K (the 2K stage): NOT open-sourced.** It is in-context *regeneration* by the base model (not a conventional SR module): 768p result + original context → 2K. Official reply (HF discussion, org MiniMax): open-sourcing "once this set of technologies becomes stable". Community roadmap: (1) H3-Regenerate-2K, (2) sparse-attention reference code, (3) unified image gen/edit model — no dates, no licenses. Until release, the official 2K workflow is hybrid: local H3-Base + hosted Context-IR + `/v2/video_regeneration` API.
- **Fast/few-step:** nothing official except the PDD Acc LoRAs below. Community turbo LoRAs (larryvrh, Alberto454, ModelTC 4–8-step) exist but have known weaknesses (audio quality, fast/intense motion smear; >8 steps = over-sharp artifacts). **Raúl's standing call: do NOT use turbo/few-step LoRAs for the cinematic series** — quality drop too large; H3 at default 20 steps stays the standard.
- **PDD Acc 8-step (official Alibaba PAI) — ADOPTED, default since 2026-08-31.** `alibaba-pai/MiniMax-H3-Acc-LoRAs` (FL2VA + Ref2VA, 8-step) + node pack `Jalen-Burnson/ComfyUI-MiniMax-H3-PDD-Acc` (core PRs in master v0.34.0+18). Recipe is fail-closed: 4/6/8 steps, euler, CFG 1.0, LoRA strength 1.0, sigma shift 12/3; the node rejects other step counts. A/B on the 5090 (controlled, same prompt/seed/refs): 5s FL2VA 480p 58.7s→35.9s (1.63×); 15s Ref2VA 1344×768 3 refs 914s→410s (2.23×) — no visible degradation, dialogue present. `generate_video.py` runs PDD-on by default (SigmaShift→Apply→guider, sigmas from Apply); `--no-pdd` = classic 20-step `res_multistep`, only on explicit request. Distinct from community turbo LoRAs: PDD is the "safe" speedup (no severe-artifact reports; turbo = ghosting/posterization/corrupt audio).
- **FastH3 V2 (FastVideo/UCSD + Nuva Lab + NVIDIA FastGen) — consumer GPUs + ComfyUI (Oct 2026).** Successor of the Aug Preview v1 (which was B200-only, T2VA-only, not ComfyUI-compatible — superseded). 8-step DMD2 distill, video+audio, single-file ComfyUI repacks (`FastVideo/FastVideo-FastH3-8-Step-V2-NVFP4-Comfy`, NVFP4 13.6 GB for Blackwell) via the "FastVideo FastH3: Text to Video" template (ComfyUI ≥0.36; our core 0.39 has the required `BlockSparseAttention` VSA node in core, sm80+). **Ref2VA (multi-reference conditioning) was NOT distilled in V2** — V2 covers T2VA + first/last-frame i2v only; r2v masters stay on base H3 + PDD (see FastH3-Omni below for the distilled ref build). The shared `minimax_h3_video_vae_int8_convrot` (lightweight LynnReal decoder path) is already on F:\ComfyUIModels. **Verdict: candidate draft engine for ref-less T2VA/i2v prompt iteration; never for R2VA masters.**
- **FastH3 Trim (Oct 2026):** V2's 8-step distill pruned 50→42 transformer blocks + rank-16 timestep conditioning; 4.2× smaller than base H3 (NVFP4 11.9 GB, int8_convrot 18.9 GB). The "runs in 8 GB VRAM" headline = NVFP4 on a 4090 with software-capped memory, not a real 8 GB card. Team labels it experimental (busy scenes lose detail) and recommends V2 when quality matters. **Verdict for the 5090: not worth it** — no Ref2VA, no VRAM pressure here.
- **FastH3-Omni (FastVideo + Nuva Lab, open weights + training code, Oct 2026) — the distilled REF2VA.** 8 fused evals (PDD 32-interval student + VSA sparse attention), full omni references (≤9 imgs / ≤3 videos / ≤3 audio, first/last keyframes, clip continuation, exact-audio) — identical reference budget and prompt structure to base H3 Ref2VA, so existing r2v prompts/reference plans carry over 1:1. NVFP4 QAD (Blackwell) + FP8/BF16 builds, ComfyUI day-0 (`FastH3-Omni-NVFP4-QAD-Comfy`, shared TE/VAE), optional 36-layer NVFP4 VAE decoder. The official RTX 5090 profile defaults to 480p and offloads the text encoder (precomputed AdaLN table). The 5.6–11.9× headline is full serving recipes on 8×GB200 vs base 50-step — NOT vs our PDD 8-step (same step count); the realistic 5090 gain is less offload from the smaller NVFP4 footprint.
- **FastH3-Omni quality signal (community, first days):** speed reports genuine down to mid-range cards; the quant FORMAT is not the loss axis — NVFP4 measured ≈ INT8 ConvRot (QAD closes the gap). The loss axis is the distill + sparse attention: "waxy" faces, mosaic fine detail when zooming sub-1MP, more garbled co-generated audio; the team concedes difficult motion, fine detail, and some audio stay below base. Complaints cluster on 8–16 GB cards under heavy offload; community guidance: with VRAM/RAM headroom, base + light distill LoRA (≈ our PDD setup) gives better quality at similar speed. **Verdict: PDD baseline stays; any switch goes through the standard A/B gate on the production graph (same seed/prompt as an approved clip, NVFP4-QAD-Comfy vs PDD), judging faces and fine detail fullscreen.**
- **Veda sparse attention (ICML 2026, ByteDance/HKU/USTC) — official ComfyUI node `veda-sparse-attention` (needs core ≥0.38; ours is 0.39).** MODEL-in/MODEL-out attention override — does NOT change weights: compatible with PDD LoRAs, quantized checkpoints, and T2VA/FL2VA/**R2VA**. Triton INT8 kernel skips ~90% of attention tiles; its arithmetic is identical to SageAttention's (1.344% err vs fp32, same as Sage's) → no new quantization cost on top of the Sage-patched graph. sm120 verified (Windows 5070 + RTX PRO 6000). Predictor = 275 MB preview trained on T2VA/8NFE, geometries incl. 1344×768 at 5/10/14 s; declared modality-agnostic, but **R2VA quality awaits human A/B** (dedicated R2VA fine-tune announced). A user-reported flicker did NOT reproduce in their 10-seed metric tests. Do not stack with core `BlockSparseAttention`/Model Sparse Attention (the node warns). Measured e2e vs the SageAttention baseline: 4090 1.77× @5.2 s → 2.42× @10.1 s → 2.82× @14.4 s; RTX 5070 1.78× @5 s; RTX PRO 6000 r2va 20-step 1.76×. **Verdict: the first sparse-attention release that clears the "large jump" bar — A/B on the production graph (PDD + R2VA) with the standard battery before adopting.** **A/B RAN 2026-10-11: NOT adopted** — 1.35× at 8 s on our graph (plan under-skips small grids; gains do scale with length as predicted), audio no-issue via exact-audio, but the R2VA preview predictor drops the mic stand/cable and drifts framing on our pilot (details + infra notes in h3-generation.md Veda entry). A dedicated R2VA predictor ckpt (`minimax_h3_r2va_veda_preview_fp8.safetensors`, 600-update fine-tune on 5.17 s R2VA clips) exists and was what we tested — the announced *stable* R2VA fine-tune is the revisit signal; `--veda` stays installed for it.

## FLUX 3 (Black Forest Labs, launched 2026-07-23)
- Omni multimodal: one architecture for video + native synchronized audio (≤20s), image gen/edit, and action prediction.
- **FLUX 3 Video: Early Access, API/partners only** — 720p native, 1080p via upscaling, by-request access, no public pricing.
- **FLUX 3 Dev (open weights): announced, NOT released** — "later this year" is the only timeline; no BFL repo on HF yet. Precedent: FLUX.2-dev announced Nov 2025 → weights Dec 2025 (weeks); FLUX 3 is far more ambitious → expect later (Q4 2026 guess, not a promise). Expected license: Dev tier (open weights, non-commercial).
- Quality signal (2026-08): H3 Elo 1,238 (independent, #2 on board) vs FLUX 3 ~1,135 (vendor-run human preference, unverified). H3 also leads on documented native 2K and ecosystem maturity. Expect *comparable*, not a clear replacement — A/B with Raúl's ears when weights land.

## PixelUMM (NVIDIA + Waterloo) — verified 2026-10-02
- **REAL, quiet release**: HF repo `nvidia/PixelUMM` created 2026-10-01 with no blog/press; arXiv 2609.38597; code Apache-2.0 but checkpoints under NVIDIA One-Way Noncommercial License (research only).
- Encoder-free unified UMM (understanding + generation, text/image/video) directly in pixel space — NO VAE, NO ViT. Qwen3-8B backbone, Mixture-of-Transformers (shared attention + understanding/generation experts), 15.2B total. Generation = pixel-space flow matching; understanding = AR text. T2I, T2V (default 4s 176×320; F18 checkpoint 832×464), image-VLM, video-VLM. **No audio, no i2v/reference/identity.**
- Checkpoints: `S8-F22-R05` default (all 4 tasks); ~128 `.distcp` shards (~30 GB BF16) + repo-specific DCP loader. Self-reported VBench P2 83.24, GenEval 0.83, MVBench 70.53 — aesthetic quality weak (61.58 vs Wan2.1 66.07). H3 not in their comparison set. Known defect: grid patch artifacts at high CFG with the linear head (conv heads fix it, unreleased).
- Runtime friction: Linux x86-64, Python 3.12, CUDA 13 dev toolkit, FlashAttention built from source (documented archs 80/90/100 — sm_120/RTX 5090 NOT documented); T2V runs Cosmos guardrails by default (gated, skippable); ~30 GB = tight on 32 GB; no Diffusers/ComfyUI nodes.
- **Verdict: watch, don't install** — research artifact (unification / encoder-free architecture study), not an H3 replacement (4s / 480p / no audio / no refs / noncommercial). Revisit on: license change, consumer-GPU repro, Diffusers/community nodes.

## Research patterns that worked here
- "Officially working on X" claims trace to: HF model card + org replies in the repo's discussions tab (authoritative for MiniMax), and bfl.ai blog + model page (authoritative for BFL). Vendor "roadmap" claims also surface in community discussions — verify against the org's own forum replies before reporting as official.
- Independent Elo (Artificial Analysis board) > vendor win-rates for cross-vendor comparison; always label vendor-run numbers as unverified.
