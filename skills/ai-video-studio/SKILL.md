# AI Video Studio

Umbrella for Raúl's local AI video pipeline: MiniMax H3 (cinematic clips, dialogue, lip-sync), LTX 2.3 i2v (scene animation), ComfyUI image models for keyframes (FLUX.2 Klein, Z-Image-Turbo, Qwen-Image 2.1), ACE Step 1.5 (songs/scores), ffmpeg (assembly, mix, upscale). Everything runs local on the RTX 5090 through the ComfyUI broker. Absorbs the former h3-cinematic-video, ai-video-post-production, and music-video-production skills.

For the underlying script APIs (`generate_video.py`, `generate_image.py`, `generate_song.py`, ref2va modes) load the `comfyui-local` skill first (scripts in `/root/.hermes/skills/media/comfyui-local/scripts/`).

## When to use

- Generating or debugging AI video clips (H3 cinematic, LTX i2v)
- Music videos — generated songs or lip-sync over an existing track
- Narrative shorts — dialogue + original score + SFX
- Post: stem separation, mixing, 4K upscale, 24→60 fps, YouTube publishing

## Engine selection

- **H3 (Ref2VA/r2v, i2v, first/last keyframes)**: characters, dialogue, native SFX, identity across shots. 4–15 s @ 1344×768 24fps. `--aspect 16:9` only (21:9 invalid).
- **H3 motion-context chain (`--h3-chain N`) — SOLO cuando hace falta (policy Raúl 2026-10-19, revisada tras ver/oír la unión en el humo)**: ≤15 s va en MONOLITO por defecto — un render único no tiene unión y normalmente sale bien. Usar cadena solo para: (a) duración continua >15 s (pastilla del monolito), (b) one-take largo que el usuario pida explícitamente, (c) nota sostenida/frase que no cabe en un render. Para regenerar una parte de un monolito sin cadena: (1) recortar la cabeza buena + encadenar la cola desde el mp4 (vía frames, pérdida mínima en el enlace), o (2) regenerar la cabeza con el driver de cadena y estirar fino. El audio nativo recosido es lo más perceptible de una cadena (nivel/agudos en cada unión): si el plano lleva pista maestra o narración por encima, se disimula; si no, adviértelo al entregar. Flags y re-ruedo por slot: comfyui-local skill y su referencia minimax-h3-guide.md.
- **LTX 2.3 i2v**: landscapes/atmosphere/gesture from a keyframe. 12 s max (errors accumulate at the tail). NEVER prompt "singing" — LTX co-generates audio that clashes with your track.
- **Keyframes**: FLUX.2 Klein 9B (environments, text-heavy), Z-Image-Turbo (fast character i2i), Qwen-Image 2.1 (multi-ref identity compositing), H3-Still/Fizgig (identity-preserving multi-ref image edits). H3-Still edits run through the edit arm of `/root/workspace/imagenes/ab-h3still/battery.py` (no standalone h3_image.py exists): copy the ref images into `battery.INP`, set `battery.SEED`, call `battery.h3_job(name, {"kind": "edit", "refs": [...], "prompt": ...}, out_png, res)` — canvas auto-sizes from ref 1 (~2.5 MP, multiples of 32), ~2.5 min/image via the broker.
- **ACE Step 1.5**: songs and scores (`references/music-generation.md`).
- **HyperFrames**: motion graphics from HTML — its own skill (`hyperframes-video`), not this one.

## Generation — always-on rules

- Broker BATCH wall-time ≈ model load (~10 min) + Σ per-job + ~3 min/job overhead. A client wrapper `timeout` shorter than the batch wall-time kills the client while ComfyUI KEEPS RENDERING the whole batch — results then live only in `C:\ComfyUI\output\<prefix>\`; recover by copying the newest `_NNNNN_.mp4` per prefix after verifying `nb_frames` equals the expected chunk length (reconcile script pattern). Always set the wrapper timeout ≥1.5× the estimated batch wall-time.
- Runs take 5–15 min: launch with `background=true` + `notify=true` in the SAME terminal call (bare notify is rejected; the foreground cap kills runs). If a run looks stuck, ground truth is `ls -lat /mnt/c/ComfyUI/output/`, not session memory. If the wrapper script died (interrupt, broker 500) AFTER the render completed, the video is still there as `openclaw-local-output_<name>-<seed>_00001_.mp4` — copy it into the project instead of regenerating; its audio may be H3's co-generated track instead of the ALAC remux, which is irrelevant in a master-song build (only mouth timing matters — verify with Whisper).
- **`SOURCE_FILENAME: openclaw-upload-*.mp4` in the log = wrong file was saved** (seen when the run used `--reference-video`: the script picked the normalized reference UPLOAD instead of the render). The real render is `/mnt/c/ComfyUI/output/openclaw-local-output_<name>-<seed>_NNNNN_.mp4` — and on a RE-RUN with the same name ComfyUI does NOT overwrite: it writes `_00002_`, `_00003_`…, so find the newest with `ls -lat`, never assume `_00001_`. Detect the wrong file: its video holds only the reference's frames (nb_frames ≈ ref-seconds × 24) stretched over the full-length audio, and `ffmpeg -ss` frame extraction silently yields an empty file. Rebuild from the render: `ffmpeg -i <render> -i <segment.wav> -t <dur> -map 0:v -map 1:a -c:v libx264 -crf 15 -pix_fmt yuv420p -r 24 -c:a alac <out>.mp4` (tail-trim keeps sync), then re-QA.
- Sampler: PDD 8-step default (2.23× faster, no visible degradation); `--no-pdd --steps 20` only on explicit request.
- H3 saves output WITHOUT `.mp4` — rename immediately after every generation.
- NEVER `-c:v copy` on H3 clips — non-standard keyframes yield empty files; re-encode `libx264`.
- NEVER let H3 render native text — it hallucinates/misspells/truncates; use `ffmpeg drawtext` in post.
- `--image` + `--reference-image` cannot combine (broker rejects); first/last keyframe mode takes keyframes only (no refs).
- **FL2VA animates the DELTA between the two keyframes — exploit it deliberately.** The endpoints' differences are what gets animated: pose change (lean-in → kiss) and even a LIGHTING SHIFT (KF pair identical except red/blue vs amber stage lighting gives a smooth in-clip light change, a cheap staged mood turn). Keep framing identical between endpoints — a camera mismatch invents an unwanted camera move. FL2VA carries no exact-audio and no refs, so the clip's soundscape (applause, ambience) is H3 co-generated — verify no invented speech (no-speech rule at behavior level too). Ref2VA reference budget: ≤9 `--reference-image` + ≤3 `--reference-video` + ≤3 `--reference-audio`, ≤12 mixed total; `--preserve-reference-audio` requires exactly ONE `--reference-audio` — plan keyframe + identity refs + motion video + exact audio within that budget.
- **r2v anchors the OPENING FRAMING to the composition reference image, not to the prompt text**: a wide-shot composition ref makes the clip open wide even when the prompt demands a tighter waist-up start (verified twice — the text lost to the image every time). The model invents the rest of the camera choreography freely. Framing-critical shots go i2v (`--image`) so frame 0 is the still; to genuinely open tighter in r2v, CROP the composition reference itself (ffmpeg/PIL) to the desired opening framing and pass the crop as the ref — text alone never tightens it.
- **Multi-shot edits work inside one r2v generation**: an explicit SHOT PLAN in `detailed_description` ("SEVERAL SHOTS with hard cuts on the beat, like a real music-video edit: mostly WIDE band shots alternating with TIGHT close-up of the singer, ONE brief cut to the drummer, ONE to the guitarist") yields a believable multi-angle sequence from a single 15 s exact-audio clip — lip-sync survives the internal cuts because the whole clip is one audio slice. The model may also insert its own cuts during a pan: don't reject them — show them to the user, who may love them ("los cortes son muy buenos, nos vale"). For verses where only one character sings, add "ONLY <char> SINGS: the others' mouths stay CLOSED" + per-character negatives (`black cat singing, drummer singing with open mouth`) and put "only <char>'s voice, no other vocals" in the soundscape. Caveat: the model REFLOWS a timed SHOT LIST — internal cut times drift (secondary shots can balloon +2–3 s, truncating the singer's); if the user rejects a multi-shot clip because an instrumentalist is on screen too long, do NOT re-roll the alternation — generate a SINGLE locked close-up of the singer alone and do the alternation deterministically in post by splicing short inserts borrowed from other approved clips (see Hybrid splice).
- Variant refs of the same character make H3 morph the protagonist toward one variant at the clip's end — pass the main individual's ref only (+ at most a generic design ref) + "must remain the same individual throughout" + negative `morphing, identity change, transformation`.
- Inspect refs with vision before writing "as in the reference" — describe the ACTUAL state (dark vs glowing eyes); over-fixing one defect introduces the opposite one, so re-verify after every fix. When ITERATING an existing prompt, re-verify its feature clauses too: a wrong clause carried forward from an earlier version ("same green eyes" when the ref has amber) overrides the identity ref in every clip made with it — pin the true feature in the prompt AND in the negative (`green eyes`) and keep it fixed across all future clips of that character.
- **i2v "exact input photo" prompts: vision-transcribe the SOURCE image before writing the prompt** — never describe the scene from conversation memory. Verified failure (mesa_4p, 4 clips): the photo was a 5-person selfie (glasses man, brunette in foreground, beige-bomber man, trench-coat woman, stubble man); the prompts described 4 invented friends (grey beards, black strap top, blonde ponytail) → frame 0 matched the real photo but mid-clip H3 replaced the real people with the fictional ones from the text. The prompt's wrong description wins over the anchor as the clip progresses.
- **Per-clip delivery beats batch**: when the user says "envíame cada vídeo conforme se genere", generate ONE clip → verify (frames + vision) → SEND it → next clip. A single `notify=["ALL DONE"]` batch with no per-clip handoff means the user gets nothing for hours, and if the final notification turn dies (user interrupt) they get NOTHING AT ALL — every clip generated, zero delivered. For batches use per-item notify patterns (one per `END <name>` log line) and deliver each clip as it fires.
- H3 invents English dialogue even with "no speech" in the soundscape — layer the no-speech rule at the character-behavior level too (`references/h3-audio-lipsync.md`).
- Character refs drag their own ROOM into the shot (hard cut to the ref's location) — name the ref's room in `subject_definitions` and ban it, mark `partially_preserved` (face/hair/costume only), negative `different room, <ref's objects>`.
- **Stage-continuity audit BEFORE generating a new angle of the same scene**: whoever was established as staying on stage (e.g. the drummer who stayed behind while the band walked off) must be visible in the background of EVERY later shot — the user spots missing background characters instantly. Review the stage state of all approved clips of that scene first; put side characters into the keyframe via NB edit ("add <char> seated at <prop> in the <position> background, small, half in shadow, keep EVERYTHING ELSE EXACTLY the same", then a darkness-match pass against the approved keyframe — these edits tend to brighten the scene), and pin them in the prompt with a timed behavior rule + negatives `<char> missing, empty <prop>, <char> leaving, <char> in the foreground`. If their close-up will later be INTERCUT with this shot, give the background character the SAME timed performance phases as the close-up (soft → crescendo → crash → freeze) and verify phase alignment by zone-motion measurement (crop the character region, frame-diffs at 10fps, compare per-phase means).
- **Multi-character composites drift SIDE characters**: a group scene built from N individual refs reproduces the front/center characters faithfully but reinterprets peripheral ones (skin tone, markings, guitar model). Fix by EDITING the group image (NB multi-ref: `-i scene.png -i char_ref.png`, prompt "replace ONLY the <character> on the <side> so he matches the second image exactly … Keep his position and pose. Keep EVERYTHING ELSE EXACTLY THE SAME: <enumerate the other characters, set, lighting, framing>") — never regenerate the whole scene.
- **Chained NB edits inflate bodies**: each successive edit of the same image tends to thicken limbs and enlarge heads (arms bodybuilder-thick, singer's head plush-big after 2-3 passes). Re-anchor proportions by feeding the edit the character identity sheets PLUS the canonical approved wide shot: "fix ONLY body proportions — arms/head must match the identity images; use the canonical image for body sizes ONLY, do NOT copy its lighting" — and vision-compare a singers crop against the canonical crop before delivering. Chained edits ALSO drift held-prop composition (a mic migrates to the wrong paw / the frame-interior side on nearly every pass despite "keep the SAME paw" wording) and creep the brightness up (re-demand "keep the dim lighting, truss OFF"). When the SAME compositional constraint fails twice in edits, stop chaining and regenerate FRESH from scene + identity refs, describing the physics as seen from that camera angle ("viewed from behind, the microphone is mostly hidden by her own head, forearm and elbow visible on the outer LEFT side") — an explicit physical description converges on the first try where edit loops thrash. For MIRRORED camera views (shot from behind the subjects, audience POV) where every text edit flips the held prop to the wrong paw: neither model reasons about mirrored laterality from text — get the constraint RIGHT in the normal view first, horizontally FLIP that image (`ffmpeg -vf hflip`) and feed it to Qwen-Image 2.1 multi-ref as the POSE ref, with the approved inverse-layout image as the second ref; the model copies a mirrored pose image reliably where prose thrashes. For REPAIRING an approved-but-flawed keyframe, Nano Banana multi-ref (scene first, identity/geometry ref second) beats Qwen-Image 2.1 and H3-Still edits, which inflate heads on face-repair passes; if NB's first pass barely changes the target feature, switch tools instead of rolling more, and when NB moves a character and breaks set geometry (stage edge, floor depth), feed the ORIGINAL scene image as an extra ref and order it to rebuild only that geometry.
- **Match a character to a scene using an IN-CONTEXT ref, not the white-background portrait**: the model copies lighting/skin/style from whichever ref shares the scene's context. A studio-portrait ref shifts skin tone and detail even when the studio portrait IS the canonical identity; pass the character's approved shot from the same environment (stage photo, same lighting) as the matching ref, and SAVE that in-context ref in the project (`personajes/<char>-play.png`) for all future uses. EXCEPTION — when the defect to repair is the character's own DESIGN (coat length/groom, face age), the in-context ref is the WRONG ref: it drags the edit toward its own rendering (an "adult and furry" approved frame made NB resolve a husky into a shaggy wolf mane — rejected). Fix design defects from the approved keyframe with the OFFICIAL CHARACTER SHEET as the sole identity ref: vision-transcribe the sheet's actual groom into the prompt ("clean well-groomed short husky ruff, NOT a long shaggy wolf mane"; "almond blue eyes, NOT round puppy eyes") + "do NOT copy its white studio background or flat studio lighting — keep the scene's dark stage lighting"; use the in-context ref only for lighting/exposure matching. QA by cropping the character's region and vision-comparing against the ref, plus a full-scene vision pass for collateral damage.
- Sustained force/emotion decays to neutral in the last 2–3 s of 10–15 s clips — verify the LAST frame; cut shorter or edit around the energetic middle. Same decay hits MOUTH STATE on long sustained notes: the singer closes the mouth early (mid-note "breath") even under exact-audio. Counter with an explicit MOUTH-OPEN HOLD RULE ("mouth must stay OPEN AND MOVING from X to Y — must NOT close, NOT nearly close, NOT drop to a hum, NOT take a breath; it closes ONLY at Z") + negatives `mouth closing early, mouth closed before <Z>, taking a breath mid-note`, and re-roll the seed (early closure is seed-dependent). INVERSE FAILURE on SHORT sung clips (≤5–6 s exact-audio): the model never sustains the open mouth at all — sealed from ~1 s into continuous singing despite lip anchors (verified: 5 s clip closed at t=1.1 with singing running to 4.3+); the fix is to generate LONGER (≥7 s) + MOUTH-OPEN HOLD and trim in post, not to re-roll the same short window. THREE MORE SUSTAINED-NOTE PITFALLS (verified cierre-ohhh, 8 rolls): (1) GIRAFFE NECK: a keyframe whose muzzle points >~30° up + a long sustained note = model resolves it as a HOWL and stretches the neck progressively; prompt neck-rules DO NOT fix it (3 failed rolls) — the KEYFRAME WINS, so make the keyframe muzzle near-horizontal. (2) INHERITED NEGATIVES: negatives written for the early-closure problem (`mouth closed, stops singing, both mouths closed at the end`) later PREVENT the natural close when the note ends — rewrite negatives whenever the failure mode flips; prompt can't beat negative. (3) H3 IGNORES EXPLICIT TIMESTAMPS ("close between second 3 and 4" had no effect) — it follows the audio envelope; judge sync by measuring mouth-close frame vs vocal RMS, not by re-stating times.
- **MICROPHONE ANCHOR for sung notes**: while a performer's voice is audible they must stay AT their microphone — head choreography that leaves the mic while the voice continues reads as bad dubbing (Raúl). When a sustained note makes posture drift (giraffe neck, leaning away), do NOT choreograph the head freely: anchor it — the stand mic is FIXED at mouth height and the open mouth stays pressed to it the whole clip, so the mic physically caps head height and the note is held with chest/shoulders, not head. And NEVER fix a timing/lip-sync problem by slowing the clip down — the slowdown drags every other motion (musicians, crowd) and is rejected; regenerate with a better prompt.
- **A prop handoff at the clip start steals the first phrase's lip-sync**: when the singer receives a prop (mic hand-off) in the opening seconds, H3 keeps their mouth CLOSED until the prop arrives even under exact-audio. Mandate "her mouth is ALREADY OPEN at frame 0 and sings THROUGH the handoff — the <prop> reaches her mouth by X.Xs, the mouth never closes while the prop moves" + negatives `mouth closed during handoff, singing starts after prop arrives`. Verify by extracting frames at the first phrase's Whisper word timestamps and vision-checking mouth state.
- **A cheering non-singer still lip-syncs — only a CLOSED jaw is reliable**: "mouth open cheering wordlessly" fails (H3 shapes the jaw along the melody) and even a pinned fixed shout shape ("holds ONE wide wordless shout shape, never articulates") still reads as singing in most rolls — H3 lip-syncs ANY open mouth in an exact-audio clip. The reliable fix is to close it: "<char> is a HYPE MAN, not a vocalist — jaws stay CLOSED in an excited grin the whole clip; he cheers with his BODY (fists, arms, steps, jumps), never with his mouth", scrub every other open-mouth clause from the prompt (a leftover "roars wordlessly" in one phase reopens it), and add negatives `<char> mouth open, <char> jaws open, <char> roaring, two mouths moving at once, <char> singing, <char> lip-sync`.
- Named real people: build ONE stable Qwen-Image 2.1 caricature portrait (`refs/<name>_retrato.png`) and reuse it in every scene image and H3 ref line — never let H3 invent a generic figure (recipe in `references/h3-generation.md`).
- Qwen-Image 2.1 DUPLICATES a character when its ref is passed — pin the count in the prompt ("EXACTLY ONE <char> in the whole image") and regenerate until vision confirms one instance.
- Physical props: state HOW they are supported (lying flat, contact shadow) or H3 draws them floating/standing.
- **Props mutate late in a clip** (a stand-mounted mic goes handheld, changes style, vanishes in the last seconds): add an explicit stability rule in `detailed_description` ("the same <prop> stays <state> in EVERY frame from first to last — it never morphs, never changes style, never becomes handheld, never disappears") + negatives `prop changing style, prop morphing, prop becoming handheld, prop disappearing`; verify the LAST frame specifically. A wrong prop style baked into a REFERENCE image propagates to every clip that uses it — fix the ref image first (NB edit), and when the prop looks right in an APPROVED clip, extract that frame and promote it to the canonical prop ref for all future clips.
- **Handheld props FREEZE when over-constrained**: demanding "holds the <prop> ALWAYS, no stand anywhere" makes H3 lock the prop motionless in mid-air (robotic arm, unnatural). Describe LIVE-PERFORMER PHYSICS instead: arm bends/extends with the sway, the prop drifts gently up/down and varies its distance to the face (close on loud notes, pulls back between phrases) + negatives `prop frozen in fixed position, prop locked in mid-air, robotic arm, stiff arm`. Then verify across several frames that the prop's position actually VARIES.
- **Cyclical gestures freeze off a static pose IMAGE; anchor them with a reference VIDEO**: prompting a repeated motion (fist-pump, wave) with a still of the pose makes H3 freeze the limb for the whole clip. Pass the gesture as `--reference-video` (2–15 s, 24 fps — extract it from an earlier approved clip where the motion looked right) + "reproduce this exact motion, NEVER frozen" + negatives `frozen arm, stuck in the air, static fist`. The video ref anchors MOVEMENT only — framing/composition still come from the reference images (though a strong motion ref can pull the framing toward its own scale: verify the shot type). ALWAYS strip the motion ref's audio (`ffmpeg -an`) when it travels alongside `--reference-audio` — its embedded soundtrack interferes with the exact-audio slice (Raúl standing rule). **The motion ref also anchors the SOURCE'S MOVEMENT QUALITY**: if the donor clip's style is wrong for the character (bouncy, young, springy), the renders keep that bounce even under "use ONLY its rhythm and timing, NOT its bouncy body" prompts plus anti-cartoon negatives — verified twice, motions stayed near-identical across re-rolls. After ONE such failed attempt, DROP the `--reference-video` and describe the motion in prose instead (body weight, adult grounded mechanics, which body parts drive each gesture); prose motion comes out varied and natural where the video ref locks it.
- **Static camera for multi-phase choreography**: when a clip follows a timed shot list of interactions (touch collar → cover mouth → handover), a "slow push-in" makes the model treat the CLOSE-UP moment as the start of the action — subjects stand frozen until the camera arrives, and the wide stage framing (floor, crowd strip) disappears mid-clip. Demand camera COMPLETELY STATIC / locked framing + "singing from the very FIRST FRAME" + negatives `push-in, zoom in, framing changes, frozen at the start`. When the user wants camera life instead ("que la cámara no esté estática"), grant a gentle push-in + lateral drift but CAP it: state the end framing and its completion point ("the push-in completes by 60% of the clip; the final framing stays medium-wide with ALL N performers visible") — an uncapped "very slow push-in" overshoots into a two-shot and crops the side musicians out of the last seconds. When flipping a shot from static to dynamic, DELETE the `camera movement, pan, orbit` negatives inherited from the static era — they silently veto the newly requested move. A FULL 360° orbit is beyond H3: a believable orbit runs ~15–20°/s and needs ≥18 s (over the 15 s cap); forced ~50°/s attempts reverse direction mid-clip and freeze the background/crowd — offer a ≤90° arc around the subject instead, with the composition keyframe containing the background the arc will reveal.
- **Instrumental performers: the keyframe pose dictates stroke COUNT.** A still with sticks/strokes raised WOUND-UP teaches H3 one resolution: exactly ONE strike then freeze. For a multi-stroke performance (fill, groove), the keyframe must show the LOW READY-TO-PLAY pose (sticks resting just over the snare) + a rate-phrased rule in `detailed_description` — "one stick stroke per audible hit, never faster than the music: sparse hold → accelerating fill of ~N strokes → biggest stroke on the loudest audible hit → sticks freeze above the ring, then completely still" — and the negatives must NOT ban `drum fill, drum roll, multiple hits` (negatives always target the CURRENT failure mode; inherited ones silently sabotage the new ask). If stroke timing drifts, do NOT regenerate — fix by PLACEMENT: measure stick-zone motion bursts and choose `in_start` so bursts map onto the master's hits (instrumental clips have no mouth → head-trim is safe); recipe in `references/h3-audio-lipsync.md`.
- **Two-character touch scenes need PAW OWNERSHIP**: without it the touched character raises its OWN paw to its own face (looks like it's shushing itself) and the toucher holds her mic with both paws. State: "<toucher>'s free paw is the ONLY paw that ever touches <target>'s neck/muzzle; <target>'s paws stay low on his mic-stand pole / at his side" + negatives `<target> paw touching his own face, <toucher> holding microphone with both paws`.
- **Contact-action keyframes (kiss/nuzzle): spell out the GEOMETRY or the model returns a nose-boop.** "they kiss" renders muzzle-tips touching, which reads as a boop, not a kiss (user rejects it). The phrase that converts it to a real kiss: "heads TILTED toward each other in opposite directions until their MOUTHS MEET AND GENTLY OVERLAP beneath the noses, noses resting slightly apart, mouths soft CLOSED (no tongue, no teeth), eyes closed" + keep bodies/props pinned. Nano Banana multi-ref converts this in ONE pass; Qwen-Image 2.1 multi-ref is WORSE at muzzle contact than NB — it opens one eye, merges the two microphones into a double-head cluster, and drifts to a profile camera that breaks the FL2VA pair.
- **Per-character prop state conflict when a prop ref pins the other state**: if two characters must hold the same prop differently (one on a stand, one handheld), a ref image showing the stand-mounted version induces stands for BOTH — drop that ref for the handheld character and assign prop state explicitly per character in the prompt ("THE HUSKY'S mic stays clipped on its stand; THE CAT'S mic is held in her paw, NO stand next to her") + per-character negatives (`microphone stand next to the <char>`). A prop state already approved in a clip frame is the best ref for it — extract and use as composition ref. A POSE ref image leaks its props the same way in NB keyframe edits — a mic held by a character in the close-up pose ref reappears in that same character's paw in the wide-shot edit, duplicating the other character's prop: state in the edit prompt "<char>'s paw is OPEN and EMPTY, no object" and verify the prop COUNT with a zoomed crop before delivering the keyframe.
- **Crowd shots**: anchor the crowd with the project's approved crowd still as a strong_reference (label it CROWD REFERENCE in `subject_definitions` and say do-not-copy-its-band-members into the crowd), pin the crowd species in the prompt ("HUMAN audience" when the band is animals) + negatives `animals in the crowd, empty crowd, static crowd, seated audience, crowd of one person, deformed hands`. An unanchored crowd shrinks, freezes, or animal-izes.
- **Per-word lip-sync failure → SYLLABLE-TIMING RULE**: when the mouth misses a specific word (typically its first syllables), map Whisper word timestamps onto clip time and add a LIP-TIMING RULE to `detailed_description`: the shot opens with the mouth ready but the first syllable NOT yet sung, then the problem word spelled out syllable-by-syllable at exact times ("her mouth shapes ru-ti-na at exactly 3.3s, jaw moving with each syllable"), the sustained vowel stretching to its mapped end + negatives `mouth already mid-word at the first frame, syllables swallowed`. Pair it with a CAMERA RULE (stable tripod framing) + negatives `fast zoom, sudden push-in, camera jerk` — a fast zoom during the sung word also reads as desync. Before re-rolling, check FACE SIZE in the opening frames: a tiny face in a wide opening shot reads as lip-sync failure even when the mouth moves on-beat — the fix is a tighter opening, which in r2v requires cropping the composition reference (see the opening-framing rule), not prompt text.
- **Performance emotion follows the LYRICS**: "poco expresiva" is a rejection reason — translate each phrase's meaning into acting beats in the prompt (ironic line → eye-roll, smirk, free-paw flick, shrug; long final word → lean into the mic, head tilt back, natural rock belt with eyes nearly shut, snap off with a smirk), split into timed phases, + negatives `expressionless face, neutral face, blank stare, monotone performance, static posture`.
- "New H3" claims (turbo LoRAs, sparse attention, 2K): triage against the local baseline before installing anything — PDD already owns speed; latent upscalers are the ~0.8MP stopgap; official 2K is API-only and cloud is not adopted (too expensive). Real A/B first (`references/h3-generation.md`).
- FastH3-Omni (8-step distilled + VSA + NVFP4 QAD) TRIAGED and REJECTED: community reports waxy faces, fine-detail loss and weaker audio vs base H3 (NVFP4 itself measures ≈ INT8 ConvRot; the cost is the distillation). With VRAM headroom the community ranks standard model + light distill LoRA (≈ our base+PDD setup) ABOVE the distilled builds on quality. Keep base+PDD; only revisit if a real A/B on a canonical seed shows parity.

## Audio — always-on rules

- Ad-hoc Whisper without a project venv: `uv run --no-project --with faster-whisper python3 - <<'EOF' … WhisperModel("medium", device="cpu", compute_type="int8") … EOF` (system python lacks faster_whisper; CPU int8 respects the no-VRAM broker rule).
- **Whisper word timestamps CUT OFF sustained notes (belts/melismas)**: the per-word `end` stops at the syllable, not at the sung note's decay (verified: "leyendas" word-end 211.42, real note death 213.9 — the user's ear was right). To measure a belt's true end, compute the RMS envelope of the demucs vocals stem (f32le hop in numpy, or astats per window) and find the drop + the silence gap before the next phrase; when the user disputes a Whisper timing, re-measure with the envelope before defending the transcript. Whisper also hallucinates on dense sung zones with long windows — use 2–5 s windows or trust energy.
- **First-pass lyric transcripts mis-hear words**: when the user quotes a line that differs from the project's stored transcript, re-transcribe that zone with short-window Whisper on the master before planning the clip window — the user's quote is usually the one that matches the audio (the stored transcript is the suspect).
- **Do NOT identify the singer from F0 of a vocals stem in a dense mix**: pyin locks onto ~400 Hz mix harmonics and returns the same median for known-male and known-female control spans. Validate any such heuristic on control spans with known ground truth first; if the controls are indistinguishable the method is blind — ask the user who sings instead of concluding.
- Verify audio objectively before accepting any dialogue/singing clip: Whisper transcript + GLOBAL similarity vs the expected line (threshold 0.93 — the keyword score alone passes broken clips); exact-audio clips get a cross-correlation vs the source segment (1.0000 bit-a-bit, ≈0.998 lossy remux, ≈0.03 = the model regenerated it) (`references/h3-audio-lipsync.md`).
- H3 co-generates garbage before/after real lines (recited prompt, invented names, trailing words): fix the prompt (first-word rule, silence-after-last-word) and try deterministic ffmpeg cut/splice BEFORE spending a regeneration attempt — it costs seconds, not GPU minutes.
- A deterministic cut must cut VIDEO + AUDIO together — an audio-only cut leaves the mouth moving in silence ("voz cortada, labios moviéndose"); re-verify with Whisper after any cut.
- ALAC-in-MP4 sounds silent on Windows players — always produce a `-c:v copy -c:a aac -b:a 192k` playback version before delivery; the ALAC master stays as archive.
- Check the script log for `Audio replaced with original (ALAC lossless)` — a narrow grep hides the `Warning: could not replace audio`.
- H3 adds unwanted voices to SFX-only clips: prompt "Silent, no speaking, no dialogue"; if it happens anyway, extract video-only for the concat.

## Assembly & mixing — always-on rules

- Complex montages: a data-driven `build.py` (CLIPS list: seg/src/start/dur/sfx; the still is ALWAYS last, `.png`, dur=0) — reproducible and self-verifying, never hand-built ffmpeg chains (`templates/build_template.py`). The `seg` name IS the temp filename and must be UNIQUE across the whole CLIPS list: a new entry reusing an earlier entry's name makes the later extraction silently overwrite the earlier segment's temp file — the earlier slot renders the wrong content and the timeline shifts, while the build's tiling self-check passes because it only validates the metadata map. Grep existing `"seg":` values before adding entries, and QA cuts on the finished montage grid before declaring a build done.
- Lip-sync is guaranteed by construction, not by luck: each singing clip is generated from its OWN exact slice `song[song_start..song_start+dur]` with `--preserve-reference-audio` and placed at that SAME timeline offset; the final audio is ALWAYS the master song, never H3's co-generated audio (`references/h3-audio-lipsync.md`).
- Concat: concat demuxer with the list in a FILE (heredoc stdin fails); exact duration via `-t <total>`, never `-shortest` (it truncates early with stills).
- Multi-track SFX: pre-mix each SFX (volume → `adelay` ms → `apad`) into its own full-duration silent track, then one `amix=normalize=0` — inline delays >30 s cause non-monotonic DTS corruption; `duration=first` truncates; `normalize=1` attenuates by input count.
- Music: full independent track, original gain, no `atrim` unless the edit demands it; verify music-only spans sit within ±1 dB of the source.
- Stems: BandIt v2 (DnR v3) for H3 joint audio; keep speech+sfx, discard H3's music — but inspect the music stem for misclassified impacts first (`references/post-production.md`).
- Dialogue ducking: one continuous duck from before the first line to after the last; never restore between adjacent lines; word-level sidechain only if it doesn't pump.
- Replacing one narration clip in a cohort: two-pass loudnorm to the cohort MEDIAN LUFS (never raw gain when it would breach the true-peak ceiling), keep duration, gate at ±0.5 LU, restart cached previews.
- 4K final masters: **DLSS SR 3×+NR (preset M) is the approved default** (A/B beat Lanczos — no ringing; NR recipe and the resumable full-master runner live in `dlss-comfyui-video`; scripts published at `cocobot-hermes/dlss-pipeline`). Lanczos stays for quick/off-GPU previews.
- 24→60 fps masters: **DLSS FG is the approved default** (beats AMT-L; hard cuts stay hard ONLY with pre-split at calibrated cuts). After per-shot FG, ALWAYS re-cut planes to the global 60fps grid (`m60_fix.py` recipe) — per-shot rounding otherwise accumulates ~200 ms of lip-sync drift by the end. RIFE/AMT-L remain fallbacks; all GPU steps go via the broker, which pauses the agent (expected).

## Verification — always-on rules

- Start/mid/end frames → vision on each; for screen-content defects the LAST frame is where they live; confirm the fixed defect is gone AND no new one appeared (over-fixes are common).
- **Prefer NATIVE vision for project QA** (image loaded into my own context, I answer the checklist myself) over a separate VL annotator: only native vision can cross-check against project-specific canon (set layout from `banda-escenario.png`, eye color, mic-stand side, prop rules) — a generic annotator reports a mic stand on the WRONG side as "fine" and misses set-fidelity defects the user immediately sees. The separate VL endpoint also OOMs/times out on big grids. Use `region` crops for fine detail; keep grids ≤16 cells ≤400 px to control context cost.
- Multi-shot clips: QA shot ORDER with a TILE GRID — `ffmpeg -i clip.mp4 -vf "fps=2,scale=480:-1,tile=5x4" -frames:v 1 grid.jpg` then vision-label every frame with its shot type in one call; scattered frames miss the wrong opening shot, missing alternation, or stalled ending. Run the same grid over the FINISHED montage around each changed span (frame n maps to t = offset + n/fps) to confirm every cut lands at its intended timestamp before telling the user the build is done. Keep grids ≤16 cells at ≤400 px/cell — the vision endpoint OOMs (`layer 39 never rang (out of memory)`) or times out on larger sheets; retry with a smaller crop around the span instead of giving up on vision.
- User reports a "salto"/jump at a clip boundary: extract frames from the FINISHED montage at cut−0.3 s and cut+0.3 s (`ffmpeg -ss <cut±0.3> -i montage.mp4 -frames:v 1`) and vision-compare — two separate generations never agree on pose/head-angle/prop position, so the fix is regenerating the span as ONE continuous clip (H3 max 15 s, one exact-audio slice covering the whole phrase), not smoothing the cut.
- Whole-clip motion QA: feed the clip to the local VL model (`llama-cpp-video-input` skill) — static frames miss drift, timing, incoherent motion; cross with the Whisper transcript for lip/action sync.
- Crowd/freeze shots: numeric band diff vs frame 0 + vision on a frame strip (static strip = frozen; arms sweeping across it = robotic wave).
- Text/silhouette formation: per-region pixel counts per frame — the region must stay ~0 px until the final ~1.5–2 s and then ramp; anything earlier is a crossfade fake.
- ffprobe before upload: resolution, duration, fps, frame count.

## Iteration workflow (how Raúl works)

- Default: deliver the MP4 to Raúl FIRST, verify in parallel — he reviews the clip himself. Exception (his explicit call): autonomous batch builds — full per-clip QA (vision: scene holds, character intact + single instance, mouth moves, no morphing/text artifacts; Whisper ≥70% keywords, es ≥0.6), max 3 attempts at seed+1, deliver only passing clips; kill runaway builds with `process_manage kill` on the session_id.
- Present the prompt + reference plan per shot BEFORE generating. When the user points at a moment in a previous video ("como hacía en el minuto 41 al 44"), the timestamp may be mm:ss or plain seconds — resolve it by extracting a frame grid from EACH candidate span of the approved montage and vision-matching the described action before planning; the named span then becomes the `--reference-video` extraction source (audio stripped). Before extracting or generating anything, check whether that beat already has a driver script (`grep -l <beat> scripts/seg_*.sh`): when the user asks "why don't we use the same frames as before", REUSE that driver's reference set and prompt skeleton verbatim — a fresh keyframe for an already-proven beat just reintroduces the side/prop/paw swaps the old canonical refs had solved, and the user spots the swap instantly. When the user names an end phrase ("hasta donde dice X"), Whisper the zone first with `word_timestamps=True` and place the cut at that word's END + ~0.05 s — never at the user's approximated second or at an onset anchor, which slices mid-word (a word's end can sit a full second after its onset; the audio master is continuous so only the video exit moves); then compute the span from the current video end and check it against the 15 s H3 cap; if it does not fit, present options (cut at the next inter-phrase gap and leave the remainder for a separate clip, or split into two clips) and let him pick before launching.
- Two variants per shot (fixed distinct seeds, `_v1`/`_v2`); regenerate with the SAME seed to isolate a prompt change; change seed only to escape a bad roll. Corollary verified (collar5 vs collar6, same seed 77): same seed + same exact-audio slice + same identity refs renders NEAR-IDENTICAL motion even when the prompt text is rewritten — fine prompt edits and composition-keyframe SWAPS only fix local attributes (prop style, eye color, face/coat rendering), they never re-roll the global choreography/timing — a same-seed regen after swapping in a repaired keyframe reproduced the approved blocking exactly. If the user says "salió prácticamente igual", the fix is a NEW SEED, not another prompt revision.
- **Partial approval is a first-class outcome**: when the user likes a clip only "until second N" (a later shot has bad lip-sync), keep the good head — cut at the INTER-PHRASE GAP from Whisper word timestamps (e.g. word ends 81.68, next starts 82.18 → cut 81.70), always `in_start=0` + shorter `dur` (trimming the tail keeps lip-sync; trimming the head shifts the mouth against the master). Regenerate only the rejected span as its own clip later; the still/filler takes the gap meanwhile. For an `--h3-chain` shot, re-roll the failing SLOT with `--chain-start <slot>` instead of cutting (same seed to isolate a prompt change, new seed to re-choreograph); for a MONOLITH (the ≤15 s default), the two rescue routes are trim-head+frames-path tail, or rebuild the head as a chain base.
- **Hybrid splice beats regeneration**: every clip generated from the same exact-audio slice shares that slice's timeline (t=X ⇒ song_start+X), so generations of the same span can be spliced with ffmpeg freely and the hybrid stays lip-sync-locked — the build treats it as one clip entry. Three moves: (a) user likes variant A's start and variant B's end → splice at a point that is an INTERNAL shot boundary of BOTH (find with scene-detect `select='gt(scene,0.15)',showinfo` + 2fps grid) so the seam is itself a plausible camera cut. Splice EXACTLY at the donor's internal cut timestamp, never "near" it: cutting ~0.17 s late leaks the donor's next-shot frames (a few 24fps frames) before the new clip and reads as a glitch the 1.6-fps QA grid can't see (verified: v19 seam jump, fixed v20 by cutting at the detected 4.208333 + repeating the donor's last frame as a hold to pad to the required splice time — a ≤0.2 s frozen hold reads as a sustained pose); verify seams on the FINISHED montage at ≥12 fps (`-ss X -t Y -vf fps=12,tile`); EXCEPTION: when the user names an exact splice second, honor it exactly — he is protecting shot length he likes; verify the seam there and do not move it. JUMP-CUT RESCUE between two near-identical close-ups of the same subject (two generations never agree on pose): a short cross-dissolve may STILL read as a jump (Raúl rejected a 0.27 s xfade) — what worked is a static digital PUNCH-IN on the incoming shot (crop ~1.2x centered on the subject, lanczos back to full size, HARD cut): a cut to a clearly TIGHTER framing reads as intentional camera emphasis. Release the punch exactly at the incoming clip's NEXT internal shot cut (scene-detect it) so the widening is invisible; keep the punch only while that subject fills the frame, never on subsequent wider/other-subject shots. (b) the incoming cut from the previous clip is visible at the new clip's head → splice a 0.3–0.5 s insert borrowed from another approved clip (e.g. the drummer) that REPLACES the new clip's first 0.3–0.5 s — replace, never prepend: prepending shifts the mouth against the master; (c) user likes the clip "until about second N" → run scene-detect and cut at the clip's OWN internal cut nearest N so the exit into the next shot/still reads as a camera change, not an amputation. A hybrid can also interleave several SHORT (0.5–1 s) inserts from other approved clips at instrumental gaps (Whisper word timestamps) to break a long single shot into a multicam-feel edit; concat the pieces video-only (normalize scale/fps first) and remux the song slice `-ss <song_start> -t <dur>` from the master as the hybrid's audio, then re-verify corr and every seam at ≥12 fps. Splice video only; the build's master audio covers the rest.
- **Parallel-angle intercut**: to alternate two angles over the same musical span, generate each angle from the SAME exact-audio window [W..W+d]; then any slice [X..Y] of either clip may be placed at master position W+X (`in_start=X`, `song_start=W+X`) — sync holds by construction and hard cuts between angles land on the beat. The "jamás in_start>0" tail-trim rule only protects clips placed at their window start; slicing a shared window is safe for both lipsynced and instrumental footage. Keep the same seed and identity refs across the two angles so pose and lighting agree at the cut points, and deliver review clips as the full intercut build, not the raw angles.
- **Sustained scream/howl mouth**: "jaws opened extremely wide / SCREAMING" renders a snake-jaw / unhinged-gape monster. Describe a real singer instead: "NATURAL singing shape like a rock singer holding a high note, teeth visible, jaw shaped by the note but NOT grotesquely stretched, muzzle keeps natural proportions" + negatives `gaping mouth, jaw unhinged, snake mouth, tonsils visible, muzzle stretched`. For shot-ORDER demands ("must start on the drummer", alternate every ~2s), prose rhythm FAILS — give a SHOT LIST with time brackets ("SHOT 1 [0.0-1.6s] DRUMMER…") + "MUST start on X, NOT on Y" + the note continuing UNBROKEN across cuts.
- **Keyframe gate**: when the user asks to see the keyframe before the video is generated, the still IS the approval artifact — generate it, vision-verify it, send it, and wait for explicit OK before spending a GPU clip on it (a rejected keyframe costs seconds in NB, a rejected clip costs 10 GPU-minutes). SEND means ATTACH the image to the reply message (MEDIA:) — an internal vision pass is NOT delivery: a turn that generates a keyframe must end with it in the user's hands, and when an iterated fix was made, attach the corrected version (plus the rejected one for comparison) even if the turn also did other prep work. When the keyframe iterated to vN, re-point the seg script's `--reference-image` to the approved version AND grep the script for the version suffix before launching — a driver left on the previous version silently burns a GPU roll carrying every old-keyframe defect.
- **An approved keyframe is FROZEN**: after the user OKs a keyframe, later clip failures are fixed via prompt/negative/seed — re-editing the approved keyframe needs explicit approval first ("no, el keyframe no lo cambies"), because repair passes reliably degrade other regions (inflated heads, broken set geometry). When a clip defect traces to the keyframe's own pose (e.g. muzzle 30° up causing a howl), show the diagnosis and a proposed replacement keyframe and wait for OK before generating.
- When Raúl queues several regenerations, generate and deliver them ONE AT A TIME and do not start the next until he explicitly validates the current one.
- Deliver any review clip TRIMMED to the exact span it will occupy on the master timeline — an over-long tail leaks the NEXT section's vocals into his review and reads as a lip-sync/audio failure.
- After approval: keep ONLY the approved asset in the working dir; move the rest to `descartadas/` (applies to refs and clips).
- When re-showing an iterated shot, attach the previous version in the same message (he compares old vs new while the render runs).
- Action/stunt shots: full-adrenaline face (screaming, wide-eyed) — serene "hero" faces are rejected; at speed, include wind/clothes physics (he checks plausibility).
