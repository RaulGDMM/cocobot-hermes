# Qwen3.8-27B A/B — n-max 2→3 + temp 1.0→0.8 (2026-08-15)

## Context

- Model: Qwen3.8-27B Q6_K + MTP GGUF, llama.cpp 0.1.0-dev build 10430 (commit 4c1a0af40), RTX 5090 32GB, serving at `http://<YOUR_LAN_IP>:30000` (Windows PC Gaming; WSL must use the LAN IP, NOT 127.0.0.1).
- Launch script: `/mnt/e/Workspace/Hermes/start-hermes.ps1`.
- Baseline server log (199 tasks, pre-change): TG <10k ctx median 101.3 t/s; 10-20k ctx ~79 t/s; 50-100k ctx 70-83 t/s. Spec stats: acceptance 65.3%, meanlen 2.5. PP 2800-3200 t/s.
- Perceived slowness root cause: `reasoning_effort xhigh` + `preserve_thinking: true` (more thinking tokens at ~70-85 t/s), NOT raw decode speed.

## Changes (applied to qwen38 profile only, all other profiles untouched)

1. `start-hermes.ps1` line ~211: `OPENCLAW_LLAMA_MTP_DRAFT_N_MAX` → `3` for qwen38 (else 2). Flows to `--spec-draft-n-max` (line ~400) alongside `--spec-type draft-mtp,ngram-mod`, `--cache-type-k/v-draft f16`, `--spec-default`.
2. `start-hermes.ps1` line ~194: qwen38 `OPENCLAW_LLAMA_TEMP` `1.0` → `0.8` (else 0.6). Flows to `--temp` (line ~324). **LATER REVERTED to 1.0** — official Unsloth recommendation for Qwen3.8 (thinking-only) is temp=1.0, top_p=0.95, top_k=20, min_p=0, presence_penalty=0. The 0.6 in the "else" branch is the NON-thinking-mode value and does not apply to thinking-only 3.8.

### Mechanism confirmation (server log, post-change)

`mean len` rose from ~2.5 to 2.76–3.33 → the 3rd drafted token is actually being accepted; the +7.3% is real, not variance.

### Caveats

- Both runs against the LIVE single-slot server (serving the Hermes chat) → absolute TG ~10-15% below log median (101.3 t/s). A/B delta is still valid (identical conditions).
- Cells tg=128 @ pp4096/16384 show little/no gain: ngram-caching was warmer in the "before" run for those repeated prompts. Not a regression.
- `llama-bench.exe` does NOT exist in this build — use `llama-benchy` (uvx) client-side instead.

## Final config (after user revert of temp)

- `--temp 1.0` (official Qwen3.8 thinking-only recommendation; reverted from 0.8 on 2026-08-15)
- `--spec-draft-n-max 3` (STAYS — this is what delivered the +7.3%)
- top-p 0.95, top-k 20, presence 0 — already aligned with vendor docs
- Remaining levers (not applied): `reasoning_effort xhigh→high` (biggest real-world latency lever, degrades reasoning depth — user decision); `ubatch 1024→2048` (prefill/TTFR); NVFP4 quantization (150-250 t/s, needs download, separate approval).
